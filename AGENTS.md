# Prototype Instructions

Run the local server yourself and open the preview in the browser available to this environment. Do not give the user server-start instructions when you can run it.

Before making substantial visual changes, use the Product Design plugin's `get-context` skill when the visual source is unclear or no longer matches the current goal. When the user gives durable prototype-specific design feedback, preferences, or decisions, record them in `AGENTS.md`.

When implementing from a selected generated mock, treat that image as the source of truth for layout, component anatomy, density, spacing, color, typography, visible content, and hierarchy.

Build app UI in `src/`. Keep `.openai/hosting.json`, `worker/index.js`, `scripts/prepare-sites-build.mjs`, and `tests/sites-worker.test.mjs` intact so the same local prototype can be handed to Sites. Before a Sites handoff, run `npm run build` and `npm run test:sites`; the build must leave `dist/client/index.html`, `dist/server/index.js`, and `dist/.openai/hosting.json`.

The `/batch-place` prototype demonstrates the selected interaction direction for multi-select placement: selected pieces become a single draggable processing unit, the system fixes the final arrangement before dragging, the full-size semi-transparent preview remains stable while moving, and the release result must match that preview exactly. The visual proportions follow the supplied current mobile game screenshots (393 × 852). Player intent has priority: pieces may overlap existing pieces, and the prototype must not show collision warnings or automatically move the selected landing point.

The multi-select picker has no send/place button. Long-pressing any already-selected piece must collapse the picker and continue as the same uninterrupted pointer gesture: the selected pieces gather into a carry stack, the board shows the fixed final-layout preview when the pointer enters it, and release places exactly at that preview. A tap still toggles selection; touch movement before the hold threshold remains a scroll/cancel gesture. Releasing outside the board restores the selection state without losing pieces.

After placement, the expanded picker remains available and excludes already placed pieces. A top-of-page undo control applies to the latest batch for about ten seconds; undo removes that batch from the board, keeps the picker collapsed, moves its pieces to the front of the list, and keeps them selected.

Latest picker direction (overrides older picker notes above): the supplied mobile references are the visual source of truth for the expanded state. The expanded picker is a bottom-anchored white sheet whose highest edge stops at roughly 41% of the play-space height, matching the latest red horizontal boundary. It has large top corner radii, a centered raised white collapse tab with a downward chevron, and a compact five-column piece grid. It has no bottom action, selection status, quantity label, or toast. Selected pieces carry their own purple check/outline; once six are selected, every remaining unselected piece dims and stops responding until a selected piece is deselected. Only a stationary long-press on a selected piece gathers and picks up the full selection; ordinary vertical movement cancels the hold and scrolls the expanded list. There is no time-based automatic close. The sheet retracts downward over 650 ms only after the entire visible aggregate has moved above the sheet's top boundary. Haptic feedback occurs only when the long-press successfully gathers the selected stack. The collapsed tray exposes exactly five positions; undo-restored overflow remains later in the ordered list.

The complete play-space rectangle between the empty top spacer and collapsed tray is a valid placement zone, including the white margins outside the gray puzzle board. The top tool row is intentionally empty while preserving its original height; no back, tool, badge, settings, or placeholder text should render there.

On mobile, the prototype viewport stays fixed while the expanded piece grid itself can scroll vertically before pickup. Once pickup succeeds, the grid locks and the page never pans with the carried stack. Successful pickup uses a short double-pulse vibration where the browser supports the Vibration API; iOS Safari does not expose reliable general-purpose web vibration, so the gather animation remains the mandatory fallback feedback there.

Long-press is the only pickup gesture so users can scroll a long expanded list without accidentally gathering pieces. A tap still selects or deselects. Holding a selected piece still for 350 ms gathers the full selection; moving 10 px before that threshold cancels pickup and preserves native vertical scrolling.

The pickup must read as conservation of the selected objects, not as a duplicate overlay: when gathering begins, every selected source tile in the open grid disappears. The carried aggregate uses exactly two visible artwork layers regardless of selection count: the pressed piece is always the top layer and one other selected piece is the back layer. Those two layers converge from their real grid positions, then lift together with a single clean spring and stronger shadow; do not add a third visible layer or a separate compression beat. The carried stack settles at 1.16 scale after a 1.23 overshoot, with 2.5 px horizontal and 1.75 px vertical offsets. On devices exposing the Vibration API, the haptic fires at this exact pickup moment with a 35 ms pulse, 18 ms gap, and 45 ms pulse.

There is no onboarding guide, hand artwork, prompt, or drag arrow in the batch-placement flow. Players select pieces directly. A stationary press lasting 500 ms gathers the full selection and triggers one short vibration where the browser supports the Vibration API; movement of 10 px before the threshold cancels the hold and preserves list scrolling. The real two-layer carry animation is the only pickup feedback.

The `/star-sparkle` prototype is a dedicated star-effect tuning lab. It supports single pieces and multi-piece combinations, including dedicated 8-piece, 20-piece, and 50-piece scale cases; true jigsaw outlines, regular bounding-box outlines, and circular rings; one to four independently tunable layers; and a fixed full-edge, outward-only distribution. Large combinations auto-fit the preview while edge offset and star size stay visually consistent in screen pixels. Edge offset is adjustable in pixels, timing starts when the piece finishes snapping into place, and lifetime refers to one star from appearance through disappearance. Keep this route focused on star tuning without the E1–E8 scenario navigation, highlight controls, or completion effects used by the main prototype.

Post-four selection update (2026-08-31): after the player selects the four required onboarding pieces, every other piece becomes selectable. Do not show the long-press hand immediately.
